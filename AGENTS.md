# Development environment notes

- This is a native Go/Bubble Tea terminal application, not an HTTP app. The Base44 setup uses ttyd 1.7.7 to expose the actual launcher over HTTP/WebSocket on port 3000; do not replace it with a mock web UI. There are no external service credentials or databases.
- `.base44/Dockerfile` installs development tooling only. The application is built from the read-only bind-mounted checkout at service startup; dependencies and build cache are named volumes. The ttyd release is checksum-pinned for amd64, so Compose specifies `linux/amd64`.
- The sandbox checkout directory has mode 0700 and is root-owned. The build/watcher runs as root to read it; ttyd drops to UID/GID 1000 and starts launcher sessions in `/home/preview`. Do not switch the entire container to that user without addressing checkout permissions.
- `.base44/dev.sh` uses entr to rebuild and restart ttyd on Go/module changes. Existing browser sessions reconnect or can be refreshed. Changes to the wrapper script require `docker compose -f docker-compose.base44.yml restart launcher`; Dockerfile changes need `up -d --build`. Refresh the preview after service restarts.
- Each browser connection runs the real launcher in its own PTY. Favorites and logs persist in the `launcher-config` volume at `/home/preview/.config`. The launcher only scans desktop applications installed in the container, not the user's computer, and there is no graphical desktop/display server. An empty application list is expected; no fake applications are seeded. Escape exits the session; refresh the browser to start another.
- `main_simple.go`, `test_log_creation.go`, and `simple_log_test.go` were standalone diagnostics with duplicate `main` functions. They are excluded by `//go:build ignore` so ordinary builds work. The first two remain explicitly runnable with `go run <file>`.
- Verify startup with `docker compose -f docker-compose.base44.yml ps`, `curl -fsS http://localhost:3000/`, and `docker compose -f docker-compose.base44.yml exec -T launcher go build -mod=readonly -o /tmp/tui-launcher-check .`. The healthcheck probes ttyd's existing root page. A stronger check opens `/ws` using WebSocket subprotocol `tty`, sends JSON `{AuthToken:"",columns:100,rows:32}`, then checks the output for `TUI App Launcher`. Sending `0?` toggles help. The browser should render the terminal and accept keyboard input.
- Tests now pass with `docker compose -f docker-compose.base44.yml exec -T launcher go test -mod=readonly -race ./...`; also run `go vet -mod=readonly ./...` in the service. Integration/config tests isolate HOME, and concurrent favorites tests synchronize their add/remove phases instead of sleeping. The permission test skips root (which bypasses permissions); to exercise it, copy source to a disposable `/tmp` directory owned by UID 1000 and run tests there as that user with a writable GOCACHE. This was verified with `-race -count=3`.
- `internal/tui/viewport.go` owns list window bounds. The normal view reserves eight terminal rows, plus two for errors. Keep the selected application stable across resizing and clamp the offset after filtering/refresh. Regression tests cover both navigation directions, wraparound, resizing, errors, and empty results.
- Search match existence is determined by the returned match positions, not whether the ranking score is positive: long valid matches can have zero/negative scores. The shorter match still ranks first.
- Config Manager public operations are serialized with a per-instance mutex and favorites slices are copied at the API boundary. Config saves write and sync a temporary file in the same directory before renaming it over the old file. This does not coordinate concurrent writes across separate processes/sessions.
- TUI state/filtering lives in `model.go`, event handling in `update.go`, rendering in `view.go`, and message definitions in `messages.go`. Rendering measures styled lines with `reflow/ansi.PrintableRuneWidth`, while truncation and matching remain rune-aware. The scanner keeps first-seen order when deduplicating, replacing entries in place if a later user entry wins.
