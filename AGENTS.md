# Development environment notes

- This is a native Go/Bubble Tea terminal application, not an HTTP app. The Base44 setup uses ttyd 1.7.7 to expose the actual launcher over HTTP/WebSocket on port 3000; do not replace it with a mock web UI. There are no external service credentials or databases.
- `.base44/Dockerfile` installs development tooling only. The application is built from the read-only bind-mounted checkout at service startup; dependencies and build cache are named volumes. The ttyd release is checksum-pinned for amd64, so Compose specifies `linux/amd64`.
- The sandbox checkout directory has mode 0700 and is root-owned. The build/watcher runs as root to read it; ttyd drops to UID/GID 1000 and starts launcher sessions in `/home/preview`. Do not switch the entire container to that user without addressing checkout permissions.
- `.base44/dev.sh` uses entr to rebuild and restart ttyd on Go/module changes. Existing browser sessions reconnect or can be refreshed. Changes to the wrapper script require `docker compose -f docker-compose.base44.yml restart launcher`; Dockerfile changes need `up -d --build`. Refresh the preview after service restarts.
- Each browser connection runs the real launcher in its own PTY. Favorites and logs persist in the `launcher-config` volume at `/home/preview/.config`. The launcher only scans desktop applications installed in the container, not the user's computer, and there is no graphical desktop/display server. An empty application list is expected; no fake applications are seeded. Escape exits the session; refresh the browser to start another.
- The old root diagnostics now live in `cmd/diagnostics/{launcher,logging,log-file}/main.go`, as separate runnable commands. Use `go run ./cmd/diagnostics/<name>`; ordinary builds/tests no longer need ignore tags.
- Verify startup with `docker compose -f docker-compose.base44.yml ps`, `curl -fsS http://localhost:3000/`, and `docker compose -f docker-compose.base44.yml exec -T launcher go build -mod=readonly -o /tmp/tui-launcher-check .`. The healthcheck probes ttyd's existing root page. A stronger check opens `/ws` using WebSocket subprotocol `tty`, sends JSON `{AuthToken:"",columns:100,rows:32}`, then checks the output for `TUI App Launcher`. Sending `0?` toggles help. Raw WebSocket tests must also answer OSC 10/11 color queries and DSR (`ESC[6n`) as xterm does; otherwise terminal startup can wait for replies. The browser should render the terminal and accept keyboard input.
- Tests now pass with `docker compose -f docker-compose.base44.yml exec -T launcher go test -mod=readonly -race ./...`; also run `go vet -mod=readonly ./...` in the service. Integration/config tests isolate HOME, and concurrent favorites tests synchronize their add/remove phases instead of sleeping. The permission test skips root (which bypasses permissions); to exercise it, copy source to a disposable `/tmp` directory owned by UID 1000 and run tests there as that user with a writable GOCACHE. This was verified with `-race -count=3`.
- `internal/tui/viewport.go` owns list window bounds. The normal view reserves eight terminal rows, plus two for errors. Keep the selected application stable across resizing and clamp the offset after filtering/refresh. Regression tests cover both navigation directions, wraparound, resizing, errors, and empty results.
- Search match existence is determined by the returned match positions, not whether the ranking score is positive: long valid matches can have zero/negative scores. The shorter match still ranks first.
- Config Manager public operations are serialized with a per-instance mutex and favorites slices are copied at the API boundary. Config saves write and sync a temporary file in the same directory before renaming it over the old file. This does not coordinate concurrent writes across separate processes/sessions.
- TUI state/filtering lives in `model.go`, event handling in `update.go`, rendering in `view.go`, and message definitions in `messages.go`. Rendering measures styled lines with `reflow/ansi.PrintableRuneWidth`, while truncation and matching remain rune-aware. The scanner keeps first-seen order when deduplicating, replacing entries in place if a later user entry wins.
- `animation.go` wraps application event handling with model-owned Harmonica springs; `animation_view.go` renders terminal-cell motion. Selection/launch targets update immediately; only the marker interpolates. A single tokenized 30 FPS tick runs while any spring is active and stops on settle/quit. Resize/filter changes snap the cursor, navigation cancels list entrance, and help slides can reverse mid-transition. Deterministic animation tests advance frame messages without sleeping; the empty sandbox list means live cursor/entrance/error checks need real installed desktop entries, not seeded mock applications.
- Launch history is an optional ConfigManager extension stored alongside legacy favorites. It uses desktop-file paths (name/Exec fallback) as IDs, records only successful process starts, and rolls back memory on save failure. Default favorites/all ordering uses count / (1 + days-since-use / 7); search uses history only to break equal-score ties within the existing favorites-first grouping. Search tokens AND across name/Exec/metadata and highlight only name positions. The read-only details column appears above 80 terminal columns and shares the list panel's height; narrow layouts remain list-only. Regression tests live in history_test.go, token_test.go and features_test.go.
- Optional `settings` preserve favorites/history on save and are loaded at startup through an optional interface. `search_fields`, `ranking`, `multi_column`, and `case_sensitive` are implemented; runtime Ctrl+\ toggles are session-only. Search normalization is cached by original field text at SetItems, not by mutable favorites or slice identity. The subsequence preflight preserves scattered fuzzy matches.
- Tab/Shift+Tab cycle real desktop categories (empty means all); `/Category query` overrides the selected category for that query. Ctrl+D or Ctrl+Space toggles favorites. Alt+1–9 targets the numbered visible window, not the complete result list; Alt+Enter forces Terminal on a copied entry. Shift+Enter is not distinguishable in traditional terminal protocols.
- Mouse reporting is enabled by WithMouseCellMotion in main.go. mouse.go hit-tests zero-based terminal cells against the rendered list (origin x=2, y=7 or compact y=5), includes entrance shifts and column gaps, ignores help/transitions/details/borders, and uses a 400 ms same-index double-click window reset by keyboard/resize/data updates. Wheel input advances one row without wrapping. mouse_test.go checks geometry, launch-message delivery, wheel bounds, and ignored targets; populated browser gestures still need real desktop entries in the sandbox.
- Above 100 columns, the list uses two row-major columns with a shared details pane. Viewport offsets align to row boundaries and page steps use rows × columns; the spring cursor measures rows rather than flattened item indexes. Tests in navigation_test.go cover editing, categories, case, paging, quick-launch, terminal overrides, persisted favorites, and empty/scanning states.
- Keep the bounded scan goroutine/select: context cancellation cannot interrupt a blocked kernel/NFS syscall. A synchronous tea.Cmd would leave isRefreshing stuck until that syscall returns even after the deadline. This is intentional, not redundant work.
- Default scanner paths honor XDG_DATA_DIRS (absolute entries only, cleaned/deduplicated in declared order), defaulting to /usr/local/share:/usr/share when unset/empty. Custom NewScannerWithPaths remains independent of XDG_DATA_DIRS; both still include ~/.local/share/applications. paths_test.go covers exported desktop discovery, first-directory precedence, and existing user overrides.
- Initial application discovery starts after the TUI opens; Ctrl+R refresh and initial scans have a 10-second timeout and cancel on exit. The scanner checks context between file operations, but a blocked kernel/NFS syscall itself cannot be interrupted; the TUI remains responsive and ignores the late scan result. `Terminal=true` launches with `$TERMINAL`, `x-terminal-emulator`, or `xterm` using `-e`; a graphical terminal emulator is not installed in the sandbox preview.
